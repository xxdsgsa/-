## 〇、全站灵魂(一句话)

> **你负责方向、判断和审美,AI 负责执行。代码是手段不是目的——把重复琐碎交给 AI,把判断创造留给自己。**

贯穿全站的四个心法:

1. **想,都是问题;做,才是答案** —— 先做出来,再逐步理解
2. **方案先行,实现为后** —— 每个功能先让 AI 出方案,你审查后再动手
3. **方向盘必须在人手里** —— AI 高速输出代码 = 高速输入 bug
4. **文档是单一事实来源** —— PRD 定"做什么",技术文档定"怎么做",变更即更新

## 一、思维篇(基础篇核心)

| 心法 | 内容 |
|---|---|
| 三种核心能力 | **做得出来、改得动、能上线**——不追求成为工程师,追求独立完成闭环 |
| MVP 思维 | 先拿到第一次正反馈,而不是先学全理论;过关线验收后立刻记"下一轮优化清单",把完美主义转化为 backlog |
| 素材 > 提示词 | 先收集事实再考虑表达;"具体比抽象有用,真实比好听有用"——素材太空,AI 只能生成谁都能套用的模板 |
| 三轮微调法 | 第1轮只修明显错误 → 第2轮调风格内容 → 第3轮小幅细化,绝不一次全修 |
| Git = 后悔药 | "存一次、看历史、退回来"最小闭环;不是协作工具,是让你后面**敢大胆改**的安全感 |
| 上线是闭环不是炫技 | 有了公网链接才开始接受真实反馈;别陷入"再改改再等等"的拖延 |

## 二、文档篇(PRD 与技术文档)

### PRD 五部分

文档信息 → 需求背景(灵魂三问+用户故事) → 方案概述(Mermaid 流程图+信息架构) → 细节方案(五状态+边缘情况) → 上线计划

### AI 的理解盲区(必须显式写)

- **不写 Out-of-Scope → AI 按"企业级完整版"自由发挥**,复杂度爆炸
- 不写边缘情况(防抖、网络失败 Toast、空状态)→ AI 就不做
- 抽象词是陷阱:"好看"→"白色背景,蓝色按钮,无边框圆角";"流畅"→"0.5 秒内响应";默认值必须明写
- AI 严格按字面理解、不会脑补;让 AI 生成的内容必须标 TBD 防瞎编

### 技术文档五大组成(不可省略,可简化)

1. **数据模型**:表/字段/关系;检验标准:PRD 每个业务实体 → 有对应表
2. **API 设计**:接口路径+方法+职责;检验标准:每个功能点 → 有对应接口
3. **架构/流程图**:组件关系 + 业务流程(Mermaid 即可)
4. **第三方集成**:服务/用途/环境变量名/限流限制
5. **技术决策记录**:选型理由 + **放弃的方案及原因**

可与 PRD 合并为"项目文档",但需区分产品思考与技术决策;**变更即更新**保持文档与代码同步。

## 三、协作篇(AI 使用心法)

**核心公式:Vibecoding = Prompt + Workflow,核心是 Workflow 而非 Prompt**

| 场景 | 做法 |
|---|---|
| 标准五步流 | 探索项目结构 → 规划实现步骤 → 编码 → 测试验证 → 提交 |
| 提示词原则 | 不设角色扮演;要具体(文件路径/技术栈/约束);给 AI"不确定就明说"的出口 |
| Git 铁律 | AI 改代码非常激进,**每完成一个独立功能就 commit** |
| Plan 模式 | 新功能涉及 3+ 文件、大重构时用(只读探索+方案审批,防止改到一半发现方向错) |
| 调试公式 | 完整报错日志(原封不动)+ 操作步骤 + 预期结果;通常 2-3 轮修复 |
| 项目规则文件 | `CLAUDE.md` / `.cursorrules` / `.iderules`,三段:技术栈+编码规范(禁 any、用 pnpm)+ 禁止行为(不装新依赖、不改 .env) |

### 实战案例的血泪教训

- ⚠️ **危险信号:同一问题 AI 改 2-3 次没解决 → 立即停下**。AI 缺乏元认知,会基于错误假设反复打补丁("按了葫芦起了瓢")。人亲自定位根因,然后明确告诉它"你之前的假设是错的,真正的问题是 XXX"
- 一次只聚焦一个模块,**永远不要让 AI 一把梭实现所有功能**(AI 画布案例折腾到凌晨四点的教训)
- 每次开发后让 AI 写总结文档,下次同步进度(维持"活的上下文")
- 分工原则:人做架构决策、方案审查、根因定位;AI 做体力活(CRUD、文档、界面);自上而下设计、自底向上实现

## 四、技术篇(编码期参考)

### 推荐技术栈(教程高度一致的共识)

> **Next.js(App Router) + TypeScript + Tailwind + shadcn/ui + PostgreSQL(Neon) + Drizzle ORM + Better Auth + Zod + Vitest/Playwright**

| 决策点 | 选择 | 理由 |
|---|---|---|
| 全栈框架 | Next.js | 全栈开发效率高,AI 理解最好;TS 类型前后端共享 |
| 数据库 | PostgreSQL + Neon | 免费 Serverless 够用;JSONB 为 AI 功能铺路 |
| ORM | Drizzle | 贴近 SQL、类型安全,**Schema 文件即文档** |
| 认证 | Better Auth | 数据存自己库、TS 原生;**绝不自己写认证**;Auth.js 已进维护模式 |
| 部署 | 国内用户 EdgeOne Pages / 全球 Vercel | 用户在国内选前者 |
| 手机 App | 网页 MVP 先验证,后续 Capacitor 打包 | 代码几乎不用改 |

### 数据库清单

- Schema 用"AI 交叉论证法"(AI 1 号设计 → AI 2 号以架构师身份审查)
- 外键永远在"多"的一方且**必须手动加索引**(PG 最常见性能陷阱)
- 热量等数字字段用 numeric;UPDATE/DELETE 必有 WHERE
- 软删除(deleted_at)代替物理删除
- 三道校验防线:数据库约束(铁律)> 后端校验(主防线)> 前端校验(仅为体验)
- 业务关系(用户↔训练计划↔饮食记录)只有你能定义

### API 清单

- 第一天就定统一响应 `{success, data}` / `{success, error:{code,message}}`
- 所有写接口 Zod 校验(前端校验防不住 Postman 直调)
- 列表接口默认分页;防重复提交用联合唯一约束
- 状态码:400 系是调用者的锅(400/401/403/404/409),500 系是服务器的锅

### UI 清单

- Tailwind + shadcn/ui(AI 擅长填空、源码进项目可改)+ Lucide 图标
- 删除等破坏性操作必须 AlertDialog 二次确认
- 空状态放"创建第一个训练计划"引导
- **FitMate 移动端优先,按单列布局设计**

### 安全清单

- `.gitignore` 含 `.env` + `.env.example` 当模板,**三件套开工首日配好**
- 密钥推上 GitHub 平均 5 分钟被盗刷,且删除无效(Git 历史还在)必须重置+清历史
- 用户体重/饮食等隐私接口做**服务端权限双层校验**
- RBAC 从 admin/user 两角色起步

### 测试清单

- 测试金字塔:单元多/E2E 少而精,只测 2-3 条主流程
- **优先测统计计算(卡路里汇总算错即事故)**
- 每修一个 bug 顺手加一个测试;用 20% 的测试覆盖 80% 的风险,不追求覆盖率

## 五、部署与迭代篇

- **给别人看**:临时用 Cloudflare Tunnel 或局域网 IP `192.168.x.x:3000` 手机真机调试;隧道不过夜、绝不暴露数据库端口
- **正式部署五步**:连 GitHub → 选仓库 → 配构建(`pnpm build`)→ **单独配环境变量**(头号部署错误)→ 部署
- **域名**:花几十块买 .com 值得;免备案三板斧 = 加速区域选"全球不含中国大陆" / 用 Vercel / VPS 选香港;服务器在大陆必须备案(2-4 周)
- **上线后**:早期**盯留存率不盯用户数**;反馈用"影响范围×严重程度"矩阵排 P0-P3;访谈用 The Mom Test(谈过去不谈未来、问具体不问笼统、让用户演示);精力 80% 修 Bug + 20% 新功能;没人用的功能果断删,但删前通知

## 六、FitMate 行动路线图

```mermaid
flowchart LR
    A[✅ PRD完成] --> B[PRD压力测试<br/>补Out-of-Scope+定4个待定项]
    B --> C[技术文档<br/>五大部分+决策记录]
    C --> D[搭环境<br/>pnpm+规则文件+.env三件套]
    D --> E[分模块开发<br/>方案先行→小步提交]
    E --> F[测试<br/>统计计算+主流程]
    F --> G[部署上线<br/>早开门拿反馈]
    G --> H[迭代<br/>留存率驱动]
```

### 下一步具体动作

1. **PRD 定稿收尾**:让 AI 压力测试 PRD(评估不足、查逻辑漏洞、生成 10 个产品问题)+ 补 Out-of-Scope + 用"决策记录"格式定 4 个待定问题(存储方案/营养计算/体重记录/总结页)
2. **写技术文档**(五大部分,可与 PRD 合并):用户表/训练计划表/饮食记录表/补剂表/饮水表/统计表
3. **开工首日配置**:项目规则文件(禁 any、用 pnpm、列常用命令)+ .env 三件套 + Git 初始化
